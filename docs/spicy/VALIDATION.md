## Failures and findings

### 1. REG-07 is open (product bug; the progress doc says REG-01..10 are fixed)

Root cause: `packages/opencode/src/tool/registry.ts`, `fromPlugin` builds the plugin context as
`{ ...toolCtx, ask: (req) => bridge.promise(toolCtx.ask(req)), directory, worktree }`. The spread passes the host's
`metadata(input): Effect<void>` to plugins, whose contract is `metadata(input): void`
(`packages/plugin/src/tool.ts:18`). A plugin's `context.metadata(...)` builds an Effect nobody runs, so its progress
never reaches the host. Minimal repro: a `.opencode/tools/progress.ts` whose `execute` calls
`context.metadata({ title: "halfway", metadata: { step: 1 } })` and returns `"done"`; the host context's `metadata`
is never called. Executable: `bun test test/tool/plugin-progress.test.ts` (the `test.failing` passes while the bug is
there). Verified, not committed: adding `metadata: (input) => void bridge.promise(toolCtx.metadata(input))` to the
plugin context makes the progress arrive.

### 2. `agenthq-panel.spec.ts:17` fails on a cold Vite cache (test harness, not the product)

The first full e2e run in this new worktree had 7 failures: the 6 known baselines plus
`agent hq streams, asks for permission, resyncs on a seq gap; problems open files` (no "Allowed" on the permission
card). Root cause, from the trace and the dev server log: the Vite dev server discovers the Markdown renderer's
dependencies (`@shikijs/stream, marked, remend, katex, marked-shiki`) only when the first assistant message renders,
logs "optimized dependencies changed. reloading" and reloads the page mid-test (`[vite] connecting...` a second time,
right after `permission.resolved` arrived). The mock server hands each queued event to exactly one SSE response and its
history only holds seq 0, so after the reload the streamed events are gone and the card never resolves. Repro:
`cd packages/app && rm -rf node_modules/.vite && PLAYWRIGHT_BROWSERS_PATH=<shim> PLAYWRIGHT_PORT=3320
PLAYWRIGHT_SERVER_PORT=4320 node_modules/.bin/playwright test e2e/regression/activity-panel.spec.ts
e2e/regression/agenthq-panel.spec.ts --workers=2` failed it 4 times out of 4. With a warm cache it passed 5/5 alone,
8/8 with 4 workers, and the full run was 107 passed with only the 6 baselines failing. Every fresh worktree starts
cold, so its first e2e run fails this test. Fix options (not applied): list those packages in the app's
`optimizeDeps.include`, or warm Vite before the run.

### 3. `packages/desktop` unit tests can download Electron (upstream test hygiene)

`src/main/wsl/servers.test.ts` imports modules that `import { app } from "electron"`. Under bun that evaluates
`electron/index.js`, which spawns `install.js` when `dist/` is missing, as after any `--ignore-scripts` install
("Downloading Electron binary..." in the log). Here it unpacked the cached
`~/Library/Caches/electron/.../electron-v42.3.3-darwin-arm64.zip` (mtime Oct 10, unchanged: no network) into the
worktree's `node_modules`; Electron was not launched. On a machine without that cache the desktop unit tests download
about 120 MB from GitHub.

### 7. `901b81d8b` runs AgentKit binaries found anywhere on disk (not run here)

The 18:05 merge makes AgentKit detection, when no bridge is on `OPENCODE_AGENTKIT_BRIDGE`, PATH or
`/Applications`/`~/Applications`, ask Spotlight for every bundle with id `local.opencode.spicy.native`
(`mdfind`) and run each copy's `Contents/MacOS/agentkit-bridge --help` to pick the newest one with an ACP mode. On this
Mac the read-only query returns 4 copies, 3 under `~/Documents/Codex/**` and 1 under
`~/OpenCodeCode/OpenCodeNative-agentkit`. AHQ-07's "through the manager" provider listing (and any provider list, such
as `GET /agenthq/providers` from the Agents tab or the HTTP exercise) uses that default discovery, so running the suites
on `901b81d8b` would execute binaries from paths this validation must not touch; it was stopped at `ed429215e`, whose
detection never reached them. Product note: provider listing executes any app bundle anywhere Spotlight indexes
(Downloads included) that carries that bundle id, with no approval, and the newest by mtime becomes the bridge every
new AgentKit session launches. The new discovery tests themselves use a fake `finder`.
